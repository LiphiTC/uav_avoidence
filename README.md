# Вариант 3 — Маршрутизация с обходом зоны РЭБ в 3D

Самостоятельный проект Qt Widgets + Qt 3D по заданию из «Контрольная работа 1 ПО ОНИ.pdf», страницы 7–9. Стиль и организация окна основаны на `uav_simulator`: C++17, заголовки и реализации классов, Qt Designer, `QTimer`, отдельная 3D-сцена.

Вместо круга используется сфера. Старт и цель задаются координатами X, Y, Z; Z — высота. Зелёный куб обозначает старт, красный — цель, жёлтая сфера — зону РЭБ, синяя ломаная — маршрут. БПЛА отображается картинкой `assets/drone.jpg`, повёрнутой к камере. Все вычисления маршрута и зазоров по-прежнему используют сферу радиусом 8 ед.; картинка отвечает только за внешний вид.

## Классы

- `Zone` (`zone.h/.cpp`) — центр и радиус сферы, проверка точки и пересечения отрезка с зоной.
- `Drone` (`drone.h/.cpp`) — координаты, скорость, маршрут и состояния полёта; движение по точкам с учётом времени.
- `Environment` (`environment.h/.cpp`) — зона, БПЛА, старт/цель, проверка параметров, расчёт маршрута и его длины.
- `Scene3D` (`scene3d.h/.cpp`) — отображение объектов и маршрута, камера.
- `ExplosionEffect` (`explosioneffect.h/.cpp`) — однократное воспроизведение видео у цели при прибытии БПЛА; плоскость видео поворачивается к камере.
- `VideoTexture` (`videotexture.h/.cpp`) — кадры видео как текстура Qt 3D, удаление зелёного фона.
- `DroneVisual` (`dronevisual.h/.cpp`) — картинка БПЛА на плоскости, повёрнутой к камере.
- `FlightAudio` (`flightaudio.h/.cpp`) — зацикленный звук полёта, пауза и однократный звук взрыва по состоянию БПЛА.
- `MainWindow` (`mainwindow.h/.cpp/.ui`) — поля ввода, кнопки, таймер и телеметрия.
- `Point3D` (`point3d.h`) — координаты и операции с трёхмерными векторами.

Модель (`Zone`, `Drone`, `Environment`) не зависит от Qt.

## Алгоритм

Если отрезок старт–цель не пересекает сферу с защитным зазором, маршрут прямой. Иначе выбирается плоскость через старт, цель и центр сферы. В ней строятся касательные и дуга окружности в двух направлениях; выбирается более короткий вариант. Для коллинеарных точек задаётся устойчивая дополнительная ось плоскости.

Радиус обхода равен радиусу зоны + 8 ед. (радиус БПЛА) + 2 ед. запаса. Дуга разбивается на отрезки не более 5° с дополнительным ограничением шага: каждый отрезок сохраняет минимум 1 ед. между корпусом и зоной. Длина вычисляется по фактической ломаной. Это геометрический обход одной сферы без учёта ветра, динамики поворота и других препятствий.

Центр зоны фиксирован: (300; 200; 200). Радиус 1–180 ед. позволяет целиком разместить обход в поле 600 × 400 × 600. Допустимые координаты центра БПЛА: X/Z 8–592, Y 8–392. Точки внутри зоны или её защитного зазора отклоняются. Дробные числа вводятся через точку.

## Сборка и запуск

Нужны CMake 3.16+, компилятор C++17 и Qt 5/6 с модулями Widgets, 3DCore, 3DRender, 3DExtras, 3DInput, Multimedia. Откройте `CMakeLists.txt` в Qt Creator либо выполните из каталога проекта:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j
./build/ew_route_3d
```

В Qt Creator: **File → Open File or Project…**, выберите `Practical_03_Classes/ew_route_3d/CMakeLists.txt`, затем комплект **Desktop** с Qt 6 и **Configure Project**. Также можно открыть `Practical_03_Classes/CMakeLists.txt`. Открывать отдельный `.cpp` или импортировать каталог исходников через **Import Existing Build** не требуется.

Сообщение **No kits are enabled for this project** означает, что нужно включить комплект для проекта: **Projects → Build & Run → Desktop**. Если список пуст, включите **Show All Kits**. В **Manage Kits** проверьте наличие компилятора C++, Qt и CMake. Для текущей Linux-системы используются `/usr/bin/g++`, `/usr/bin/qmake6` и `/usr/bin/cmake`.

Включён preset **Desktop Debug (Qt 3D)** для Ninja и CMake 3.21+. Он использует отдельный каталог `build/desktop-debug`, чтобы не смешивать CMake-кэши разных генераторов. Его можно проверить из каталога проекта:

```bash
cmake --preset desktop-debug
cmake --build --preset desktop-debug
./build/desktop-debug/ew_route_3d
```

Если Qt Creator сообщает о несовпадении генераторов Ninja и Unix Makefiles, выберите новый каталог сборки, например `build/desktop-debug`, вместо ранее настроенного `build`.

1. Задайте старт, цель и радиус, нажмите «Проложить маршрут».
2. «Старт» запускает полёт; «Пауза» останавливает; после достижения цели доступен повтор.
3. Редактирование параметров удаляет старый маршрут и останавливает полёт. Постройте маршрут заново, чтобы применить параметры к сцене.
4. «Сброс» возвращает исходные параметры, очищает маршрут и восстанавливает камеру.
5. ПКМ с движением мыши вращает камеру; ЛКМ с движением сдвигает её. Колесо и кнопки меняют масштаб.

Во время полёта зацикленно воспроизводится `assets/drone_sound.mp3`; пауза приостанавливает звук, продолжение полёта возобновляет его. При достижении цели звук полёта останавливается, запускаются видео `assets/explosion.mp4` (около 6 секунд) и отдельный звук `assets/exposion.mp3`. Видео повёрнуто на 180°, зелёный фон становится прозрачным. Его встроенная аудиодорожка отключена, чтобы не дублировать звук взрыва.

Все медиа встроены в приложение через `assets.qrc` и работают независимо от рабочего каталога. Сброс, изменение параметров и повтор полёта убирают текущий эффект и останавливают звуки; следующее прибытие запускает взрыв заново. Для воспроизведения нужен мультимедийный backend Qt с поддержкой H.264 и MP3; ошибки отображаются под кнопкой построения маршрута.

При отклонении недопустимых символов в координатах/радиусе, попытке построить маршрут с некорректными значениями или точками внутри зоны/зазора воспроизводится `assets/critical.mp3`. Незавершённый ввод проверяется при нажатии «Проложить маршрут»; сброс останавливает предупреждение.

## Проверки модели

```bash
cmake -S . -B build -DEW_BUILD_TESTS=ON
cmake --build build -j
ctest --test-dir build --output-on-failure
```

Для проверки без Qt добавьте `-DEW_BUILD_GUI=OFF`. Тесты проверяют прямой путь и обход, вертикальные и коллинеарные маршруты, касание, совпадение точек, ошибочные параметры, зазор каждого сегмента, паузу, достижение цели, длинный шаг времени и 3000 воспроизводимых случайных сценариев в 3D.

При включённом GUI также нужны Qt Test; проверяются кнопки, валидация полей, сброс, пауза, повтор полёта, декодирование встроенного MP4, удаление зелёного фона и завершение/повтор эффекта.
